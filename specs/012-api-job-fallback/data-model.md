## 4. Repository Changes

### `app/mcp/repositories/job_repo.py` — new methods

#### `upsert_from_fallback`

```python
async def upsert_from_fallback(
    self,
    normalized_jobs: list[NormalizedJob],
) -> list[Job]:
    """
    Bulk-upsert fallback jobs. ON CONFLICT (dedup_hash) DO UPDATE:
    - fallback_source = 'jdl_api'
    - last_seen_at = NOW()
    Returns the upserted Job ORM objects.
    """
```

**SQL pattern**:
```sql
INSERT INTO jobs (id, dedup_hash, title, ..., fallback_source)
VALUES (...)
ON CONFLICT (dedup_hash) DO UPDATE
  SET fallback_source = EXCLUDED.fallback_source,
      last_seen_at = NOW()
RETURNING *;
```

## 7. State Transitions

### Job Lifecycle with Fallback

```
[User Query]
     │
     ▼
[DB Search] ──── hits ≥ threshold ──────────────────► [Return DB results]
     │                                                  (no API call)
     │ hits < threshold
     ▼
[JDL API Search]
     │
     ├─ Error/Rate limit ───────────────────────────► [Return DB results (may be empty)]
     │                                                  (graceful degradation)
     │
     │ Success
     ▼
[Normalize & Filter]
     │
     ├─ Invalid job ────────────────────────────────► [Drop, increment dropped_count]
     │
     │ Valid jobs
     ▼
[Upsert to DB via ON CONFLICT (dedup_hash)]
     │
     ▼
[Schedule Embeddings] (fire-and-forget)
     │
     ▼
[DB Re-Query] ─────────────────────────────────────► [Return hybrid-ranked results]
                                                       (fallback_used=True)
```

## 8. Validation Rules

| Field | Rule |
|-------|------|
| `fallback_min_result_threshold` | Must be ≥ 0. Threshold=0 means "always supplement" |
| `fallback_max_results` | Must be in [1, 100]. Spec default: 20 |
| `fallback_source` on `Job` | If set, must be `"jdl_api"` (future values reserved) |
| Strict threshold semantics | `len(hits) < threshold` (not `<=`) |
